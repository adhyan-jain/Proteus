Method: parse the control channel, label from the dataset’s own flows

1 · PARSE

44 ONOS captures (11 benign, 33 attack, 7 classes). 7.38M OpenFlow messages decoded; 134 resyncs, 12 KB lost.

2 · FEATURES

22 per 1 s window from PacketIn headers and flow-stats deltas, with 3 windows of history.

3 · LABELS

Window = attack iff a PacketIn’s 5-tuple matches an attack flow in InSDN’s CSV. Unmatched windows inside attack captures are excluded.

4 · PROTOCOL

No capture in both train and test. 10 seeds, GPU training, balanced accuracy.

Truncated PacketIns (182k, headers only) still parse, so labels are unaffected.

Labels are the part reviewers will probe. A window is labelled by matching each PacketIn’s embedded 5-tuple, in either direction, to the Flow IDs in InSDN’s own CSV. We tried an alternative that also counts IPs seen only in attack flows; it covers spoofed floods but overlaps with the IP-count features, so it is a sensitivity variant. Strict labels leave brute force, web and exploit with only 6 to 12 attack windows each; say this up front. Parser reliability: the first parser dropped the whole stream buffer on any desync and lost up to 90 percent of PacketIns on some DDoS captures; the resync fix reduced loss to 12 KB.
