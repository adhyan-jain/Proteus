# Evaluation validity in SDN intrusion detection: paper and reproduction

Paper: `paper/main.tex` (IEEEtran journal class, `paper/main.pdf`). Every number in it comes from a file in `results/`
(or from `paper/tables.tex`, `paper/live_table*.tex`, which are generated from those files). Slides: `deck/PRESENTATION.pptx` (built by `ofgap/make_deck.py`).
The study has two parts: what an SDN controller can observe in InSDN (controller-observability gap), and how much reported IDS accuracy depends on the
evaluation protocol (random vs held-out-host splits, leave-one-host-out, protocol audit of published papers).

## Reproduce
```
research/insdn_controller/reproduce.sh          # needs GPU torch in ../../.venv, data in ../../data/raw (see data/MANIFEST.md)
```
It rebuilds the controller features from the raw InSDN ONOS captures, re-runs every experiment (10 seeds), the forwarding-study
analysis and the host-side baseline, regenerates the tables, and compares each result with `results/` (`ofgap/compare_results.py`,
tolerance 1e-6). `paper/verify_numbers.py` then checks the numbers quoted in the paper text against `results/`.

Inputs and their integrity: InSDN CSVs and the ONOS controller captures (`data/MANIFEST.md`); SHA-256 of every capture used,
including the live Mininet/Ryu captures, in `capture_hashes.sha256` (paths relative to `data/raw/insdn_pcaps` for `ex/...` and
to this directory for `live/...`). Raw captures are not all in git; `live/campaign2/*_s[5-9].pcap`, `live/out_linear3/` and
`live/out_stock/` are local and checked by hash.

## Re-recording the live captures (needs root; not part of `reproduce.sh`)
```
sudo python3 live/run_benign.py --out live/campaign2   --modes mac fivetuple fivetuple_short --repeats 10 --duration 90
sudo python3 live/run_benign.py --out live/out_linear3 --modes mac fivetuple fivetuple_short --repeats 10 --duration 90 --topo linear3
sudo python3 live/run_benign.py --out live/out_stock   --modes stock --repeats 5 --duration 60
```
Packet timing differs between recordings, so counts will differ slightly from the committed ones; the committed captures'
hashes pin the numbers in the paper.

## Known gaps
* `results/live_modes_v2.json` records the flawed first campaign (cited as such in the paper); its captures were not retained, so
  it cannot be regenerated, only quoted.
* No attack traffic was generated by us; the interleaved benign+attack study is future work.
* Leave-one-host-out results use the few real hosts each dataset has (InSDN: about three attackers); they are deterministic across model seeds, so no confidence interval is computed.
* The audit covers InSDN and CICIDS2017 only; UKMDDoSDN has no benign class (see the paper's appendix).
* Prior-art statements are limited to papers read in full (`notes/PRIOR_ART_HOSTS.md`); the InSDN dataset paper itself was not available in full text.
