# P1 hostile-reviewer audit (SPEC v1.4, written after the campaign)

Scope: the preregistered P1 campaign (S1, B=100, seeds 0–9, 23 arms), the S2 P0 gate, the implementation, the frontend and the
paper. Method: re-derive from the artifacts, try to break each claim, fix what can be fixed without touching frozen evidence,
otherwise downgrade the claim. Evidence files: `results/p1_leakage_audit.json`, `results/p1_audit_sensitivity.json`,
`results/intervention_p1_S1_B100_summary.json`. Nothing below changes the preregistered verdict.

**Verdict of the audit:** the negative result stands. The strongest *positive* statements the evidence supports are narrow
(candidate quality, certification gap). Several claims the original plan hoped to make are explicitly downgraded below.

## Items fixed during the audit
- `analyze_p1.py`: removed an unused key; added the exploratory gate-blocking diagnostic and decision-trace export.
- Frontend: legacy `/models` page vs API contract; top bar; legacy banner on the demo overview.
- Paper: wording that overstated (S2 "no room at all" → "at the assessed budgets"; CPU-minutes → summed wall-clock; "shows" → "indicates"; dose-size statements tied to measured medians).

## Items that cannot be fixed without invalidating the preregistration (downgraded, not fixed)
- The controller's no-op behaviour is a property of the frozen constants at B=100; testing other constants is a new preregistration.
- Selectivity and attribution (H3a/H3b) were never tested because the sequence stopped at H2.
- WGAN-GP (P2) and S2 arms (P3) were not run because their gates did not open.
